**R-03 — Save contract and implementation differ, including replay configuration (Medium).** `specs/L0-match/07-save-minimal.md:60-61,71,133` specifies `command_log`, a `SemVer` configuration map, postcard serialization, and rejection when configuration versions are missing. `crates/pcfm-match/src/save.rs:80-98` has no `command_log` and stores string versions; `:112-119` initializes `config_versions` empty; `:131,142-143` serializes/deserializes JSON; and `:187-191` replays with `MatchConfig::default()` rather than loading or validating the saved configuration. **R-10 — GroundTruth public API and Debug differ from its stated contract (Low).** `specs/L0-match/10-ground-truth.md:75,106-111,157-159` says only `new`, resolution methods, and `drain_observations` are public and specifies a `GroundTruth { .. }` Debug representation. ## 5. Three Planes doctrine

**R-01 — Raw Plane A values leak in serialized Plane B causes (Critical).** `crates/pcfm-hidden/src/lib.rs:140-145` writes attacker and defender scores into `Factor.value`; `:182` writes `shooter.finishing`; `:213` writes `passer.passing`; and `:262` writes `player.injury_proneness`. These values are read from private latent state. `Factor` exposes public `name` and `value` and derives `Serialize` at `crates/pcfm-model/src/cause.rs:11-16`; `MatchEvent` exposes a `cause_trace` at `crates/pcfm-stats/src/event.rs:85,109`. `crates/pcfm-match/src/state.rs:118-120,141-143` forwards outcome causes into events, and `crates/pcfm-match/src/save.rs:131` serializes saves. The code contradicts the observed-only cause rules in `specs/L0-match/05-match-events.md:21-24,117` and `specs/L0-match/10-ground-truth.md:96,102,110-111`, as well as `specs/00-foundations.md:55-67,128-131`. Private `GroundTruth` fields therefore do not prevent latent values from crossing into Plane B and save data.

It also contradicts the “never exposes a latent value” claim in `crates/pcfm-hidden/src/lib.rs:5-17` and the boundary descriptions in `docs/ARCHITECTURE.md:91-92` and `docs/CODE_TOUR.md:90,113`.

Other boundary checks: `GroundTruth` has private fields and no serialization implementation (`crates/pcfm-hidden/src/lib.rs:51-57`); its Debug omits latent attributes (`:351-356`). No Plane C implementation or Plane C → Plane A feedback path was identified in the inspected L0 code. These points do not mitigate the R-01 cause-trace disclosure.

## 6. Determinism

The core registry uses a `BTreeMap` and derives each ChaCha stream from the world seed and stream name (`crates/pcfm-core/src/rng.rs:53-75,87-91`). Pattern searches found no `HashMap`/`HashSet` use in the inspected simulation implementation; the observed `HashSet` is in test-runner coverage reporting (`crates/pcfm-test-runner/src/commands.rs:8,52`). No system-seeded RNG use was found. A source scan also found the documented `expect` construction paths (R-08) and the event-handler panic propagation (R-07); these panic cases were not validated by execution, and the baseline tests were blocked. Deterministic output is therefore unverified by tests. These observations are based on source search and inspection, not on baseline test results.

**R-05 — Match decision streams omit the match identifier (Low).** `specs/L0-match/01-rng.md:44-62` requires scoped names such as `match:{match_id}:micro-decisions`, and `specs/L0-match/00-overview.md:145-150` describes streams derived with match scope. `crates/pcfm-match/src/state.rs:57-63` instead uses fixed names `match:actions`, `match:action_kind`, and `match:player_pick`; `RngRegistry` derives streams only from `(world_seed, stream_name)` (`crates/pcfm-core/src/rng.rs:87-91`). Separate matches using the same world seed therefore start these engine streams identically. This is deterministic, but does not implement the specified per-match stream isolation.

`SIM_VERSION` is `1` at `crates/pcfm-match/src/save.rs:76`, matching `CHANGELOG-SIM.md:14`. Changelog location/baseline prose is stale as noted in R-04. The mandatory checks, including the seeded test-runner check, could not verify determinism in this run.

## 7. Correctness observations

**R-06 — Attacker and defender are selected using the same roll (Medium).** `crates/pcfm-match/src/state.rs:222-229` draws one `roll` and scales it for each squad. With equal-sized squads—as in the 11-player fixtures—the indices always match, correlating each attacker with the same relative slot on the opposing squad rather than independently selecting a defender. The code describes the model as a prototype simplification (`state.rs:70-76`); the selection remains a concrete bias.

**R-07 — Event handler panics propagate instead of being isolated (Medium).** `specs/L0-match/02-event-bus.md:108,129` specifies catching/logging handler panics and continuing the match. `crates/pcfm-core/src/event_bus.rs:81-85` explicitly documents that a handler panic propagates and drained events are lost; `:126-140` invokes handlers without a panic boundary. The source labels this a known limitation, but the implementation does not meet the stated behavior.

**R-08 — `expect` remains in simulation construction paths (Low).** `docs/context/NEW-SESSION-PROMPT.md:87` D2 prohibits `unwrap`/`expect`/`panic!` in simulation paths. `crates/pcfm-match/src/state.rs:57-63` and `crates/pcfm-hidden/src/lib.rs:68-71` use `expect` to construct stream names. The current strings are literals or formatted with non-empty prefixes, so these failures appear unreachable under present inputs; they nevertheless violate the stated prohibition.
